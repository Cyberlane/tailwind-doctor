How scoring works ↗

Conservative by design

Dynamic or uncertain values are recorded as unresolved. The analyzer never invents classes just to produce a finding.

Safe for private code

No telemetry, network calls, credentials, config execution, or install-time binary downloads.

One engine, everywhere

Terminal, CI, and editor diagnostics stay aligned.

Human output, versioned JSON, SARIF, VS Code, and Neovim all share the same rule IDs and source ranges.

Quickstart

From zero to a useful baseline.

No account, daemon, or project plugin. Point the CLI at a Tailwind project and inspect the report.

  1. 01

    Run the doctor

    Use either npm package name. Both launch the same native binary.

    $ npx tw-doctor .
  2. 02

    Review the evidence

    Start with high-confidence correctness and consistency findings; configure or allowlist deliberate exceptions.

    $ tw-doctor --json . > report.json
  3. 03

    Gate only new debt

    Record the current state, then add score and extraction-coverage thresholds when your team is ready.

    $ tw-doctor --write-baseline .

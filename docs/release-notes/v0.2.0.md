# Tailwind Doctor v0.2.0

This release makes analysis coverage and editor feedback first-class without
relaxing Tailwind Doctor's local, deterministic, static-analysis boundary.

## Highlights

- `tw-doctor lsp` analyzes unsaved buffers, and the attached VSIX provides
  native VS Code diagnostics in single- and multi-root workspaces.
- `--require-coverage` gates unresolved dynamic class construction separately
  from the health score.
- JSON schema 4 adds finding end ranges and a project-wide coverage object.
- Score model 2 excludes application CSS class names from Tailwind utility
  exposure and reports zero-exposure categories as unmeasured.
- Baseline format 2 adds explicit stable fingerprints and atomic writes while
  continuing to read version 1 files.
- Static discovery now includes package-manifest-only Tailwind installations,
  `.js`, `.ts`, and `.mdx` sources, Tailwind v3 z-index tokens, and explicit
  package/version evidence in machine reports.

`variant-density` and `no-overlapping-utilities` are fully implemented but
disabled by default for their introductory minor release. Enable either under
`[rules]` to evaluate it before it can affect default reports. The retired
`responsive-bloat` identifier remains valid in configuration and reports
nothing.

## Compatibility

Machine consumers must accept JSON `schemaVersion: 4`. Scores produced by score
model 1 and score model 2 are not directly comparable. Existing baseline version
1 files remain readable; regenerate them to adopt version 2 fingerprints.

All analysis remains local. Neither the CLI, language server, nor VS Code
extension executes application code, writes source files during analysis, or
makes network requests.
